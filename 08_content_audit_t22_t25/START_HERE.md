# 从这里开始：你的实际操作

## 你将得到什么

本材料包针对修正后的 Topic 22（49 个专利族）和 Topic 25（38 个专利族），共 87 条。第一轮审查时你不会看到它们属于哪个 Topic。第二轮从中抽取 18 条，用于检查你自己的判断在间隔一段时间后是否稳定。

## 开始前

1. 先读 `CODEBOOK.md`，不要先浏览 Topic 22/25 的旧标签或 PPT 结论。
2. 打开 `01_round1_blinded_review.xlsx`，只填写浅黄色的人工字段。
3. 不要打开 `99_DO_NOT_OPEN_topic_key.xlsx`。它用于最后解盲。
4. 每次建议审 10–15 条，单次不超过 90 分钟。预计总耗时约 8–12 小时。
5. 不确定时选择 `UNCLEAR`，不要为了“完成”而猜测。

## 第一轮怎么审

对每一行按以下顺序：

1. 先读 First Claim；信息不足再读 Abstract 和 Title。
2. 判断它的主要技术功能是否直接涉及安全。
3. 分别寻找感知、判断和保护响应的明确文字证据。
4. 判断是否明确涉及 humanoid，而不是泛指工业机器人或一般机械系统。
5. 只有文本明确描述一个子系统状态/输出改变另一个子系统条件时，才标记明确跨子系统传播。
6. 复制最关键的原文到 `exact_evidence_quote`，记录来源位置。
7. 用一到三句话写 `decision_reason`；最后填写信心等级和状态 `COMPLETE`。

## 延迟复审

完成第一轮后等待 7–14 天。期间不要查看第一轮答案或解盲密钥。然后打开 `02_round2_delayed_retest.xlsx`，按同一手册重新判断18条。第二轮编号已更换，不会提示它们对应第一轮的哪一条。

## 完成后

不要自己手工对照 Topic。把两个已填写工作簿交给 Codex，或运行：

```powershell
python scripts\analyze_completed_audit.py
```

脚本只有在两轮数据完整且枚举合法时才会解盲并生成结果。最终应把结果称为“结构化单人内容审计”，而不是“独立验证”。

## 可支持与不可支持的结论

可以支持：Topic 22 在力感知、人机接触安全和保护性响应机制上是否富集；Topic 22/25 的内容纯度和机制组成有何差异。

不能支持：真实机器人中 cascade 已经发生；某主题导致事故或伤害；专利机制已实际部署；不存在传播证据等于传播不存在。
